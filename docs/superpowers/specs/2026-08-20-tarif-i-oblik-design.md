## Задача 1 — Блок «Тариф»: смена тарифа

### Что не так сейчас

1. Кнопки «сменить тариф» нет. Конструктор ± спрятан внутри
   «🎫 Моя подписка» → «🔁 Продлить / купить», то есть сменить тариф можно
   только вместе с покупкой срока.
2. Упёршийся в лимит юзер получает всплывашку «Достигнут лимит устройств
   (1/1)» и остаётся в тупике — выхода из неё нет.
3. **Дыра в деньгах.** `billing._extend` перезаписывает лимиты на весь
   ОСТАВШИЙСЯ срок, а не только на купленный. Год на 1 устройство (810 ₽)
   плюс месяц на 10 устройств (720 ₽) даёт 12 месяцев на десяти устройствах
   вместо честных 6480 ₽.

### Модель: пересчёт остатка

Неиспользованное время не сгорает и не возвращается деньгами — оно
пересчитывается в время нового тарифа:

    остаток_новый = остаток_старый × база_старая / база_новая

где база — `pricing.monthly_price_kopeks(dev, byp)`, то есть цена БЕЗ скидки
за срок. Скидка за срок не участвует в пересчёте с обеих сторон: иначе годовая
скидка 25 % множилась бы на каждой смене тарифа (купил год со скидкой, «сменил»
на тот же самый тариф — вышел с 486 днями вместо 365).

Считаем в секундах, округляем ВНИЗ. Округление вниз делает качели между
тарифами убыточными для качающего — арбитраж невозможен.

Свойства модели:
* Тариф не менялся → коэффициент 1, поведение сегодняшнее.
* Покупка = пересчитанный остаток + полный купленный срок. Влад: «раз меняешь
  тариф, то получаешь его полный срок купленного».
* Дыра закрывается сама, без отдельного правила.

### Точки применения

**`billing._extend`** — вместо `start = max(now, old_expiry)`:

    new_expiry = now + convert(old_expiry - now, old_tariff, new_tariff)
                     + months × 30 дней

При неизменном тарифе результат совпадает с сегодняшним. Автопродление всегда
идёт текущим тарифом → коэффициент 1 → не задето. Админская выдача подписки
ходит в `repo.set_subscription` напрямую, мимо `_extend` → не задета.

**Новый `billing.change_tariff`** — смена без оплаты: пересчитать остаток,
записать новые лимиты и новую дату, записать в журнал. Не трогает
`sub_term_months` (это ориентир автопродления — что юзер ПОКУПАЛ), не сбрасывает
базу трафика, не снимает `is_trial`.

### Правила и запреты

* Новый тариф не ниже текущего потребления — правило уже есть в `cb_bal_buy`,
  переносится и в смену без оплаты.
* Смена без оплаты требует активной ПЛАТНОЙ срочной подписки. Триал —
  недоступна (триальные дни не куплены, менять их не на что), бессрочная —
  недоступна (менять нечего), истёкшая — остаток ноль, только покупка.
* Если после пересчёта остаётся меньше суток — смену запрещаем и говорим
  почему. Иначе юзер одним тапом обнуляет себе подписку.
* Экран подтверждения обязан назвать обе цифры: было N дней → станет M дней.

### Экран

Один экран «⚙️ Тариф» вместо «🔁 Продление подписки»: крутилки ±, строка
пересчёта, кнопка «Сменить без оплаты» (только когда тариф правда изменён и
смена доступна) и кнопки сроков с ценами. Точки входа: «🎫 Подписка» →
«⚙️ Сменить тариф», и оба тупика по лимитам — вместо всплывашки экран с этой
кнопкой.

## Задача 2 — Блок «Облик»: дизайн интерфейса

Направление выбрано Владом: **строки-иконки** (вариант А) + **адаптивное
главное меню** (вариант 1).

### Дизайн-система

Живёт в `bot/texts/ui.py` как хелперы сборки экрана, чтобы правила были кодом,
а не договорённостью:

* **Заголовок** — одна эмодзи + существительное жирным: `🎫 <b>Подписка</b>`.
  Без «Мои»/«Моя»: раздел называется одинаково в кнопке и в заголовке.
* **Факт** — отдельная строка `<эмодзи> Название — <b>значение</b>`.
  Максимум 5 фактов на экран.
* **Справка** — `<blockquote expandable>`. Тип сущности `expandable_blockquote`
  подтверждён в Bot API. Длинные объяснения (автопродление, как считается цена,
  что будет после триала) переезжают туда: на экране одна серая строка,
  разворачивается тапом. Работоспособность разметки проверить на живом боте
  до массового применения.
* **Кнопки** — главное действие во всю ширину со `style`
  (`primary` / `success` / `danger`), второстепенные парами. Возврат —
  `‹ Назад` (одинарная стрелка), выход в меню — `‹ Меню`.
* Эмодзи только в начале строки и на кнопках, внутри предложений — нет.

### Адаптивное главное меню

Набор один, из него выпадают неуместные кнопки:

* новичок без устройств → `🚀 Подключить устройство` (primary),
  `💳 Тарифы` + `🌍 Локации`, `🆘 Поддержка` + `⚙️ Ещё`;
* активный платный → `📱 Мои устройства` (primary),
  `⚡ Резервное подключение`, `🎫 Подписка` + `💰 Баланс`,
  `🆘 Поддержка` + `⚙️ Ещё`;
* истёкшая подписка → `🔁 Продлить подписку` (primary) первой строкой, дальше
  как у активного.

В `⚙️ Ещё` уезжают: оповещения, локации, тарифы, политика конфиденциальности,
пользовательское соглашение. Юридические ссылки перестают занимать две
полноширинные строки на самом частом экране бота.

### Экраны под переверстку

Главное меню и стартовый экран, подписка, список устройств и карточка
устройства, баланс, резервное подключение, тарифы, поддержка, оповещения.

### Скил `.claude/skills/bot-ui/`

Готового плагина под интерфейс Telegram-ботов не существует — проверено по
трём маркетплейсам (286 плагинов в официальном). Поэтому дизайн-система
записывается скилом в репозитории: правила сетки, тона, названий кнопок и
работы со справкой. Цель — чтобы новые экраны собирались по одним правилам, а
не по памяти исполнителя.

Мини-приложение (WebApp) в этот блок НЕ входит: нужен домен, а сертификат
сейчас выписан на голый IP. Отдельный этап, когда появится домен.

## Задача 3 — Блок «Ревизия-2»: полная проверка

Безопасность (`/security-review`), корректность и чистота (`/code-review`),
полный прогон pytest, и ручной UX-проход по правилам: у каждого тупика есть
выход кнопкой; ни один экран не длиннее пяти фактов плюс свёрнутая справка;
одна сущность называется одним словом во всех экранах.

## Порядок работ

1. Блок «Тариф»: пересчёт в `_extend` + `change_tariff` + экран + точки входа.
2. Блок «Облик»: `ui.py`, адаптивное меню, переверстка экранов, скил.
3. Блок «Ревизия-2»: проверки и правки по их итогам.

Тесты пишутся вместе с кодом. Существующие тесты интерфейса
(`test_menu_layout`, `test_wording`, `test_pricing_screens`) обновляются под
новые правила, а не отключаются.
