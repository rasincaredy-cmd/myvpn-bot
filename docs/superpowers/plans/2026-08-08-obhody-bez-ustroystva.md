# План: резервные подключения без устройства

Дата: 8 августа 2026. Ветка: `obhody-bez-ustroystva` (от `d7fa00f`).
Решения приняты Владом 4.08.2026 — новых вопросов по составу не задаём.

## Зачем

Тариф продаётся двумя независимыми позициями: устройства и резервные
подключения (обходы БС). Экран продления прямо предлагает поставить 0 —
«Не нужны устройства или обходы — смело ставь 0». Тариф «0 устройств +
1 резервное подключение» стоит 60 ₽ и покупается, но получить по нему нельзя
ничего: создание обхода спрашивает устройство и упирается в «Сначала создай
устройство», а устройство не создать — лимит 0. Деньги списаны, доступа нет.

Вторая дыра: удаление устройства молча уносит и его обходы — и с сервера
обхода, и из базы. Юзер удалил телефон из списка, а вместе с ним пропала
отдельно оплаченная позиция тарифа.

## Решение Влада

Связь обхода с устройством остаётся **меткой, а не владением**:

1. Нет активных устройств → устройство не спрашивать вовсе, выдавать обход
   сам по себе. Поле `WdttAccess.device_id` уже nullable — этот путь для базы
   не новый, по нему живут «легаси»-строки.
2. Удаление устройства обход **не убивает**: обход теряет метку и остаётся
   в разделе «⚡ Резервное подключение».

Полную отвязку (снести поле, переписать карточку устройства, уборку
зомби-устройств, админские карточки, данные в проде) отвергли как дорогую
ради этого.

**Нюанс реализации:** метку при удалении устройства надо снимать ЯВНО —
внешние ключи в базе выключены намеренно (на этом держится `user_wipe`),
`ON DELETE SET NULL` сам не сработает.

## Задачи

### Задача 1 — обход выдаётся без устройства

`bot/handlers/wdtt.py`.

- `_ask_device`: нет активных устройств → не показывать тупик «Сначала создай
  устройство», а сразу проставить `device_id=None` и вести юзера на шаг
  выбора адреса подключения (VK). Есть устройства → экран выбора остаётся
  как был.
- `cb_wdtt_platform` (создание): `device` тянуть из базы только когда
  `device_id` задан. Ошибка «Сервер или устройство недоступны» — только когда
  устройство было выбрано и пропало, пока юзер шёл по шагам.
- Метка обхода без устройства: `Резервное подключение N`, где N — порядковый
  номер среди обходов юзера. Метка уходит в `ctl add -label` на сервер обхода
  и в суффикс `#label` ПК-ссылки, поэтому пустой она быть не может.

Тесты: выдача без устройств доходит до создания с `device_id=None`; выдача с
устройствами по-прежнему требует выбора.

### Задача 2 — удаление устройства не уносит обход

`bot/db/repo/devices.py`, `bot/services/teardown.py`.

- `repo.delete_device`: вместо `DELETE FROM wdtt_accesses WHERE device_id = ?`
  — `UPDATE ... SET device_id = NULL`. Пиры удаляются как раньше: пир без
  устройства смысла не имеет, обход — имеет.
- `teardown.delete_device`: убрать снятие обходов с сервера обхода. Обход
  продолжает работать, снимать его нечего.
- `repo.revoke_device` (отзыв по истечению подписки) обходы устройства
  трогать продолжает — это не удаление, устройство и обход гаснут вместе
  и вместе оживают.

Тесты: после удаления устройства строка обхода жива, `device_id` пуст,
пароль на сервере обхода не снимался.

### Задача 3 — отвязанный обход не выпадает из жизненного цикла

`bot/services/revive.py`, `bot/services/scheduler.py`.

Сейчас и отзыв при истечении подписки, и ревайв при продлении ходят по
устройствам юзера (`list_wdtt_for_device`). Обход без устройства в этот обход
не попадает: подписка кончилась — он остаётся живым на сервере бесплатно;
подписка продлена — он не оживает.

- `revoke_devices_for_user`: обходы перебирать по юзеру
  (`list_wdtt_for_user`), а не внутри цикла по устройствам. Ранний выход
  `if not devices: return False` убрать — у юзера без устройств может быть
  обход.
- `revive_devices_for_user`: то же самое, и бюджет `sub_max_bypass`
  считается по всем обходам юзера.
- Планировщик 2b (зомби-устройства): условие «нет обходов с этим device_id»
  после отвязки выполняется само — проверить, что устройство-пустышка
  по-прежнему убирается, а обход при этом не трогается.
- Планировщик 2a (stale REVOKED-обходы) уже ходит по всем обходам — проверить.

Тесты: истечение подписки снимает обход без устройства; продление оживляет
его; лимит `sub_max_bypass` при ревайве считает и отвязанные.

### Задача 4 — экраны, README, выкатка

- Экран подтверждения удаления устройства не должен обещать удаление обходов.
- Карточка обхода: показывать устройство-метку, когда она есть.
- README: раздел про резервные подключения — обход живёт отдельно от
  устройства.
- Полный набор тестов, слияние в `main`, выкатка на klopas, проверка логов.
