# Moschata VPN — Telegram-бот для AmneziaWG

Telegram-бот, который ставит **AmneziaWG** на твой VPS и продаёт доступ подписками: юзер заводит устройства (на каждое — конфиг во всех локациях) и доступы к обходу блокировок, платит с внутреннего баланса. Название — от *Desmana moschata*, русской выхухоли (она же маскот сервиса).

Бот не пропускает трафик через себя — это «пульт управления». Сам VPN живёт на VPS, который ты добавляешь через `/install`. Один бот может управлять несколькими серверами одновременно.

```
┌──────────────────┐   SSH    ┌──────────────────┐  WireGuard/UDP  ┌──────────┐
│ @MoschataVPN_bot │ ───────► │  VPN-VPS         │  ◄────────────  │  Клиент  │
│  (этот процесс)  │          │  AmneziaWG awg0  │                 │ AmneziaVPN│
└─────────▲────────┘          └──────────────────┘                 └──────────┘
          │ HTTPS
     Telegram (ты)
```

## Что умеет

- **`/install`** — по SSH ставит на чистый Ubuntu/Debian VPS: PPA `amnezia/ppa`, `amneziawg` + `amneziawg-tools`, заголовки ядра, DKMS-модуль; генерирует серверные ключи и параметры обфускации (Jc/Jmin/Jmax/S1/S2/H1..H4); настраивает iptables/UFW; поднимает интерфейс `awg0` и включает автозапуск.
- **Устройства вместо голых пиров** — юзер заводит «устройство» (телефон, ноутбук), а бот сам создаёт ему по конфигу на КАЖДОЙ доступной локации. Лимит устройств — часть подписки (`sub_max_devices`), конфиги выдаются кнопками по локациям: `.conf`, QR или `vpn://`-ссылка для клиента Amnezia.
- **Резервное подключение (wdtt)** — вторая единица продажи наравне с устройством: доступ к proxy-turn-vk на сервере обхода, трафик которого маскируется под видеозвонок VK и проходит там, где обычный VPN режут. Лимит — `sub_max_bypass`, платформа выбирается юзером, трафик идёт в общий лимит подписки. Юзеру раздел показывается как «⚡ Резервное подключение» — формулировки про обход убраны по требованию платёжного провайдера (см. страж формулировок ниже), техническая суть не изменилась.<br>**Живёт отдельно от устройства.** `wdtt_accesses.device_id` — метка (название подключения в списке), а не владение: юзер без устройств (тариф «0 устройств + 1 подключение» продаётся и стоит 60 ₽) шаг выбора устройства не проходит вообще и получает доступ с именем «Резервное подключение N»; удаление устройства метку снимает, а доступ оставляет работать. Отзыв при истечении и ревайв при продлении ходят по юзеру (`list_wdtt_for_user`), а не по его устройствам, — иначе отвязанный доступ жил бы на сервере бесплатно и никогда не оживал; лимит устройств на него не действует, это отдельная позиция тарифа.
- **`/invite`** — одноразовая ссылка `t.me/<bot>?start=<token>` для друга. Друг открывает → бот заводит ему устройство по всем локациям в рамках лимитов подписки.
- **Каскадное удаление сервера** — при удалении из меню бот заходит по SSH и **снимает с VPS всё, что устанавливал**: останавливает `awg0`, выключает systemd-юнит, `apt purge amneziawg*`, удаляет `/etc/amnezia/amneziawg/`, закрывает UFW-порт.
- **`/admin` — админ-панель** — юзеры с сегментами (💎 платящие, 🎁 триал, 💤 спящие, 🔴 истёкшие, 👑 админы), выдача/отзыв подписки, лимиты, ручная правка баланса, рассылка с таргетингом, статистика (устройства, обходы, конверсия, деньги за 30 дней), стирание юзера из БД.
- **Приватные серверы** — сервер можно пометить «🔒»: он выдаётся только админам и юзерам с флагом «⭐ Друг» (`is_vip`). Уже выданные конфиги продолжают работать.
- **Учёт трафика** — накопленный трафик пира хранится в БД и **переживает ребут VPS** (счётчик `awg` при рестарте обнуляется — бот ловит сброс и суммирует дельты), поэтому лимиты считаются честно.
- **Отзыв с ревайвом** — при истечении подписки устройства и доступы обхода отключаются, но их конфиги хранятся 30 дней; при продлении всё оживает само: WG-пиры возвращаются на сервер с теми же ключами/IP, wdtt-пароли восстанавливаются на сервере обхода (`ctl add -password`) — юзеру ничего не нужно перенастраивать.
- **Распределение по серверам** — юзер выбирает только локацию («🇳🇱 Нидерланды»), конкретный сервер внутри неё бот берёт сам: наименее загруженный по активным пирам (WG) или обходам (wdtt). Заполненные сервера юзерам не предлагаются ни при выдаче устройства, ни при переезде: ёмкость задаётся руками в карточке сервера — `wdtt_max_accesses` для обхода, `max_peers` для VPN-конфигов (NULL = без ограничения, 0 = выдача закрыта). В имени конфига в приложении — локация без номера сервера; локации при добавлении сервера выбираются кнопками (нет дублей из-за опечаток).
- **Смена сервера у конфига** — юзер меняет сервер сам («🔀 Сменить сервер» в карточке устройства: страна → сервер → подтверждение), админ переселяет чужой конфиг из карточки пира («🔀 Переселить», сервер бот подбирает сам в той же локации). Файл конфига при переезде обязательно меняется — у другого сервера свои ключи, — поэтому бот сразу присылает новый и прямо пишет, что старый надо заменить. Старый работает ещё сутки (`peers.grace_until`) и снимается планировщиком (секция 2d), потом живёт как обычный отозванный до ретеншна 30 дней. Переезжать можно раз в сутки на конфиг (`peers.moved_at`); на админа лимит не распространяется. Локации, где у устройства уже есть свой конфиг, в списке не предлагаются — практически это выбор другого сервера внутри своей страны, ровно тот случай, ради которого кнопка и сделана.
- **Баланс, оплата и рефералка** — юзер пополняет баланс тремя способами: карта/СБП/крипта через Platega (`PLATEGA_MERCHANT_ID` + `PLATEGA_SECRET` в `.env`, пусто = способ выключен), @CryptoBot (Crypto Pay, инвойсы в рублях, +4% бонуса; `CRYPTOPAY_TOKEN` в `.env`, пусто = способ выключен) и звёзды Telegram (наценка 25%, настройка не нужна) — подробности в разделе «Способы пополнения». Подписка покупается с баланса: тариф 90₽/мес за первую позицию, 120₽ за 1 устройство + 1 обход БС, +40₽ за устройство и +30₽ за обход сверх первого, скидки за срок (3/6/12 мес − 10/15/25%). Срок прибавляется к остатку, при истечении работает автопродление с баланса (отключаемо юзером): продлевает на **тот же срок, что юзер покупал в прошлый раз** (`users.sub_term_months`), сохраняя скидку за срок; если баланса на полный срок не хватает — берёт максимальный доступный (12→6→3→1) и пишет юзеру, на сколько не хватило, с кнопкой пополнения; не хватает даже на месяц — ничего не списывает и ждёт пополнения. Сумма и срок будущего списания называются заранее, в предупреждении об истечении. Срок покупки пишется при оплате с баланса и при админской выдаче «🎫 Выдать подписку» (тарифный срок 1/3/6/12 мес, бесплатно, с ценой на кнопках для ориентира — иначе это была бы покупка); у произвольной даты из «📅 Задать срок» понятия «сколько месяцев» нет, поле не трогается, у старых юзеров оно пустое — им, как и раньше, месяц. Реферальная ссылка `?start=ref_<id>`: пригласившему падает `REFERRAL_PERCENT` (15%) с каждого пополнения реферала. Все движения денег — в журнале `balance_txs` (копейки, без float); админ может начислять/списывать вручную (например, за перевод на карту).
- **Полный туннель, дружелюбный к клиенту Amnezia** — конфиги содержат строку `AllowedIPs = 0.0.0.0/0, ::/0` ровно в том виде, в котором клиент Amnezia распознаёт полный туннель и разблокирует своё встроенное меню раздельного туннелирования (по сайтам/приложениям — юзер настраивает сам в приложении). Фича «RU напрямую» (инверсия RU-реестра в AllowedIPs) удалена 19.07.2026: клиент Amnezia не тянет большие списки маршрутов (>~8k — туннель не стартует, >~21k — краш при импорте), а в рабочий лимит (~2k маршрутов, крупные блоки ≤ `/18`) не помещаются банки/ozon из «белых списков» — то, ради чего фича и была нужна. Такой сплит требует доменного роутинга (XRay/sing-box), в WireGuard он невозможен (нет SNI-сниффинга, только IP-маршруты).
- **Сапорт-чат** — поддержка внутри этого же бота, отдельный бот не нужен: юзер жмёт «🆘 Поддержка» → «✍️ Написать в поддержку» и пишет (текст/фото/файл), бот копирует сообщение всем админам с подписью, кто пишет. Админ отвечает обычным **реплаем** на копию — ответ доставляется юзеру в чат. Юзер продолжает переписку реплаем на ответ (режим диалога включать заново не нужно). Маршруты хранятся в БД (`support_msgs`), переживают рестарт бота и чистятся через 30 дней.
- **Бэкапы в Telegram** — раз в сутки (час `BACKUP_HOUR_UTC`, по умолчанию 03:00 UTC) планировщик снимает горячую копию SQLite (штатный `Connection.backup()`, без остановки бота) + `.env`, шифрует паролем `BACKUP_PASSWORD` (PBKDF2-SHA256 → Fernet) и присылает файлом каждому админу — Telegram хранит документы неограниченно, это и есть офсайт-копия. Кнопка «📦 Бэкап сейчас» в админ-панели — то же самое вручную. Восстановление на новом VPS: `python3 scripts/restore_backup.py <файл>` (автономный скрипт, боту для этого запускаться не нужно). ⚠️ Пароль храни и вне сервера: без него бэкап не расшифровать, а в бэкапе — балансы юзеров, все ключи пиров и `ENCRYPTION_KEY`. Пусто = бэкапы выключены (warning в логе).
- **Время — московское везде, где его видит человек** (`bot/utils/timefmt.py`): в БД хранится UTC, на экраны юзера И админа выводится МСК (фиксированный UTC+3, перевода часов в РФ нет). Ввод дат админом («📅 Задать срок») тоже читается как МСК — иначе введённое «до 23:00» и показанное юзеру время разъезжались бы на три часа. Единственное оставшееся UTC — `BACKUP_HOUR_UTC` в `.env`: это серверная настройка расписания, а не текст для человека.
- **Тарифы, документы и согласие с условиями** — требование платёжного провайдера: цены должны быть видны до оплаты, а политика конфиденциальности и пользовательское соглашение — лежать в постоянном доступе отдельными кнопками. Экран «💳 Тарифы» открыт из меню без подписки и без оплаты, все цифры на нём считает `pricing.py` из `.env` — поменяешь цену, экран обновится сам. Документы хранятся в `docs/legal/`, публикуются на telegra.ph скриптом, кнопки в меню ведут на них напрямую. Новый юзер при первом `/start` проходит экран согласия: триал и меню выдаются только после «Согласен», дата пишется в `users.terms_accepted_at`. Действующих юзеров гейт не трогает — их отличаем по дате регистрации.
- **Авто-миграции** — при старте бот сам добавляет недостающие колонки в существующую БД (`ALTER TABLE ADD COLUMN`), так что обновление на месте не ломает старую базу.
- **Безопасность**: SSH-креды шифруются Fernet, сообщения с паролем/ключом удаляются из чата сразу, FSM-storage — memory-only (после рестарта бота временные креды теряются).

## Требования к VPN-серверу

| Что | Требование |
| --- | --- |
| ОС | Ubuntu 20.04+ или Debian 11+ |
| Виртуализация | **KVM** (на OpenVZ/LXC своё ядро не загрузить — DKMS не сработает) |
| Доступ | root по SSH (пароль или ключ) |
| Cloud firewall | Открыть UDP-порт (по умолчанию `585`) у провайдера |

Это может быть **тот же VPS, что и бот** — он сходит по SSH сам на себя.

## Стек

aiogram 3.x · SQLAlchemy 2.0 async (SQLite/aiosqlite) · asyncssh · cryptography (Fernet) · pydantic-settings · loguru · qrcode · cachetools

## Быстрый старт (хост бота)

Нужно: Ubuntu 22.04+/Debian с **Python 3.11+** (на 3.10 не запустится — в моделях используется `StrEnum`).

```bash
# 1. Клонировать
git clone https://github.com/<you>/myvpn-bot.git /opt/myvpn-bot
cd /opt/myvpn-bot

# 2. venv + зависимости
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. ENCRYPTION_KEY (Fernet)
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

# 4. .env
cp .env.example .env
nano .env   # вписать BOT_TOKEN, ADMIN_IDS, ENCRYPTION_KEY

# 5. Запуск
python -m bot
```

Открой бота в Telegram → `/start` → «🛠 Установить VPN на VPS» → следуй мастеру.

## Запуск под systemd

```ini
# /etc/systemd/system/myvpn-bot.service
[Unit]
Description=Moschata VPN Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/myvpn-bot
EnvironmentFile=/opt/myvpn-bot/.env
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/myvpn-bot/.venv/bin/python -m bot
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myvpn-bot
sudo journalctl -u myvpn-bot -f
```

Экран согласия с условиями показывается при первом `/start`. Он включается,
когда задана хотя бы одна из ссылок `LEGAL_PRIVACY_URL` / `LEGAL_TERMS_URL`:
если не задана ни одна, гейт выключен — иначе юзер застрял бы на экране, где
нечего прочитать. Действующих юзеров гейт не трогает: отличаем по дате
регистрации относительно даты выката — константа `CONSENT_SINCE` в
`bot/handlers/common.py` (05.08.2026). В `.env` её намеренно нет: сдвинуть
дату задним числом означало бы показать гейт тем, кто уже платит.

Формулировки в текстах для юзера сторожит `tests/test_wording.py`: он
разбирает файлы через `ast`, смотрит только строковые литералы (комментарии и
докстринги — внутренняя кухня) и падает, встретив стоп-слово из требований
провайдера. Админские экраны в проверку не входят — их видит только владелец.
Если строка попала под шаблон, но пользователю не показывается, помечай её
`# wording: ok` на последней строке литерала, а не расширяй список исключений.

Цены считаются так (прайс пересмотрен 8.08.2026): первая позиция — устройство **или** обход — стоит `PRICE_FIRST_RUB`, и это пол тарифа; каждое следующее устройство прибавляет `PRICE_EXTRA_DEVICE_RUB`, каждый следующий обход — `PRICE_EXTRA_BYPASS_RUB`. Отсюда 1+0 = 0+1 = 90 ₽, 1+1 = 120 ₽, 2+1 = 160 ₽, 3+1 = 200 ₽. Тариф без единой позиции (0+0) не продаётся.

Формула **только складывает**. У прежней база покрывала позиции, а отказ от них вычитался, и при `база < сумма доплат` тариф уходил в минус — за этим следило правило в докстринге. Правило убрано вместе с вычитанием, вместо него стоит тест: ни один набор позиций не стоит дешевле пола.

Цена **не фиксируется** в момент покупки: автопродление каждый раз считает по текущему прайсу, поэтому смена цен действует и на действующих подписчиков со следующего списания.

### Способы пополнения

Пополнять баланс можно тремя способами, и все ведут в одну точку — `billing.credit_deposit`: журнал, бонус за способ и реф-награда пригласившему у них общие.

| Способ | Что платит юзер | Бонус/наценка | Идемпотентность |
| ------ | --------------- | ------------- | --------------- |
| Platega (карта/СБП/крипта) | рубли, способ выбирается на форме провайдера | без бонуса (комиссия 8–9 % на сервисе) | статус строки `platega_payments` = `paid` |
| @CryptoBot | рубли (крипта покупается с карты там же) | **+4 %** на баланс отдельной строкой `bonus` | статус инвойса `paid` |
| Звёзды Telegram | звёзды | **+25 %** к цене (наценка за способ) | строка `star_payments` по `charge_id` |

**Platega** — основная платёжка (карты 9 %, СБП 8 %, крипта 5 %, холд 3 дня). Счёт создаётся запросом `POST /v2/transaction/process` **без** указания способа оплаты: юзер выбирает карту, СБП или крипту уже на форме провайдера (у старого `/transaction/process` способ обязателен, формы с выбором он не даёт). Счёт живёт **30 минут**. Вебхуков нет — статус добирается кнопкой «Я оплатил» и поллингом планировщика (секция 0, раз в 5 минут); приём вебхуков требует домена с валидным сертификатом и сделан не будет, пока домена нет. Комиссию платит сервис, поэтому на баланс падает ровно выбранная сумма. Возврат (`CHARGEBACKED`) баланс не трогает — юзер мог деньги уже потратить, — а падает тревогой админам. Юзер и сумма при зачислении берутся из своей строки в БД, а не из ответа провайдера: их API по id отдаёт и чужие транзакции.

Бонус за способ — отдельная строка журнала, а не надбавка внутри пополнения: в статистике «пополнений за 30 дней» должны стоять деньги, которые сервис правда получил, а не они же плюс подарок. Проценты живут в `pricing.DEPOSIT_BONUS_PERCENT`, наценка звёзд — в `STAR_MARKUP_PERCENT`; курс звезды плавает (она привязана к доллару), поэтому вынесен в `.env`.

Звёзды **пополняют баланс**, а не покупают подписку напрямую: покупка, автопродление, рефералка и история операций уже ходят через баланс, второй путь пришлось бы дублировать в каждом из этих мест. Telegram может доставить событие оплаты повторно — от двойного зачисления держит первичный ключ `star_payments.charge_id`, он же единственное, чем звёзды возвращаются юзеру. Долю Apple/Google при покупке самих звёзд сервис не получает, и на экране пополнения об этом сказано прямо.

### Статистика считает чужих

Конверсия и «деньги за 30 дней» не видят своих: админов (автоматически) и аккаунтов с пометкой «🧰 Служебный» в карточке юзера (`users.is_staff`) — друзей, платящих вне бота, и проверяющих от платёжного провайдера. Их покупки — перекладывание из кармана в карман. Повод: 8.08.2026 экран показывал «1 из 7 покупали подписку», и этот один был тестовой подпиской владельца за 27 270 ₽ деньгами, начисленными себе кнопкой.

## Что бот делает на VPN-сервере во время `/install`

| Шаг | Команда |
| --- | ------ |
| Обновить apt | `apt-get update && apt-get install -y software-properties-common iptables-persistent qrencode ...` |
| Подключить PPA | `add-apt-repository -y ppa:amnezia/ppa` |
| Headers и DKMS | `apt-get install -y dkms build-essential linux-headers-$(uname -r)` |
| Поставить AWG | `apt-get install -y amneziawg amneziawg-tools` |
| Собрать модуль | `dkms autoinstall -k $(uname -r) && modprobe amneziawg` |
| IP-forward | `net.ipv4.ip_forward=1` в `/etc/sysctl.conf` |
| Серверные ключи | `awg genkey \| awg pubkey` → `/etc/amnezia/amneziawg/server.{key,pub}` |
| Конфиг | `/etc/amnezia/amneziawg/awg0.conf` с обфускацией (Jc/Jmin/Jmax/S1/S2/H1..H4) |
| Файрвол | `ufw allow <port>/udp` (если ufw активен) + iptables-persistent |
| Старт | `awg-quick up awg0` + `systemctl enable awg-quick@awg0` |

## Что бот удаляет при удалении сервера

Зеркало установки — best-effort, ошибки одной команды не блокируют остальные:

```
awg-quick down awg0
systemctl disable awg-quick@awg0
apt purge -y amneziawg amneziawg-tools amneziawg-dkms
rm -rf /etc/amnezia/amneziawg
ufw delete allow <port>/udp
```

PPA и `net.ipv4.ip_forward` **не трогаем** — безвредны и могут быть нужны другим сервисам.

отредактировать. Адреса готовых страниц — в `LEGAL_PRIVACY_URL` и

## Почему `PRAGMA foreign_keys` выключен

В моделях у внешних ключей стоит `ondelete="CASCADE"`, но SQLite по умолчанию FK не
проверяет, и **включать их здесь нельзя** — на этом держится стирание юзера.

`services/user_wipe.py` удаляет строку `users`, а её REVOKED-пиры и wdtt-доступы
намеренно **переживают владельца**: в них лежат ключи и пароли, которыми ретеншн
планировщика повторяет SSH-снятие, если в момент отзыва сервер был недоступен.
Включи каскад — эти строки исчезнут вместе с юзером, и живой конфиг удалённого
юзера навсегда останется на VPS: снять его будет нечем. Вся чистка идёт по
статусу и дате, владелец для неё не нужен, поэтому висячие `user_id` — ожидаемое
состояние, а не повреждение базы.

Инвариант закреплён тестами `tests/test_user_wipe.py`. Прежде чем включать FK,
нужно вынести «долги перед сервером» (что осталось снять и на каком сервере) в
отдельную таблицу, не связанную с юзером.

Отдельная тонкость: `device_id` в `peers`/`wdtt_accesses` добавлялся миграцией
`ALTER TABLE ADD COLUMN` **без** `REFERENCES`, поэтому в базе этого FK нет вообще —
`ondelete="SET NULL"` в модели существует только на уровне Python. В тестах,
где таблицы создаёт `create_all`, он есть: схемы прода и тестов тут расходятся.
Поэтому `repo.delete_device` снимает метку у резервных подключений **явным**
`UPDATE ... SET device_id = NULL`: положиться на каскад тут нельзя нигде.

## Безопасность

- **SSH-креды** хранятся в БД только зашифрованными (Fernet/AES-128-CBC + HMAC). Без `ENCRYPTION_KEY` расшифровать невозможно.
- **Сообщения с паролем/ключом** удаляются из чата немедленно после получения.
- **FSM-storage** — memory-only: при рестарте бота временные креды теряются (сознательное решение — в Redis их не пишем).
- **Логи** — `loguru` с `diagnose=False` и осторожным превью команд, чтобы секреты не уезжали в stderr.
- **AdminFilter** — административные команды доступны только `ADMIN_IDS` из `.env`.
- **Antiflood** — TTL-кеш на 0.7 с против спама / случайного даблклика.
